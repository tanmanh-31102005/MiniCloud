Thiết Kế Kiến Trúc Microservices & API Gateway Với Nginx Reverse Proxy

Tác giả: Nhóm Đồ Án MyMiniCloud | Cập nhật: 2026

"Một hệ thống phân tán mạnh mẽ luôn cần một Gateway thông minh để ẩn giấu độ phức tạp nội bộ và tối ưu hóa luồng dữ liệu của người dùng."

1. Tại sao cần API Gateway trong hệ thống Cloud?

Khi một hệ thống Cloud bao gồm nhiều dịch vụ độc lập (Web Server, Flask API Backend, Keycloak Identity Provider, MinIO...), nếu cho phép client gọi trực tiếp đến từng port riêng lẻ (8080, 8085, 8081, 9000...), hệ thống sẽ bộc lộ nhiều điểm yếu:

  • Rủi ro bảo mật: Quá nhiều cổng mạng bị phơi bày ra ngoài Internet khiến bề mặt tấn công tăng lên.
  • Phức tạp phía Client: Client phải biết chính xác địa chỉ và port của từng dịch vụ, gây khó khăn cho việc quản lý CORS và domain.
  • Khó mở rộng: Không thể áp dụng cân bằng tải hoặc thay đổi kiến trúc nội bộ mà không làm gãy kết nối của client.

2. Định tuyến thông minh theo đường dẫn (Path-based Routing)

Trong MyMiniCloud, chúng ta triển khai api-gateway-proxy-server bằng Nginx đặt tại cổng tiêu chuẩn 80. Nginx hoạt động như một Reverse Proxy thực hiện điều hướng theo tiền tố đường dẫn (URI prefix):

  • / hoặc /blog/: Chuyển hướng tới cụm Web Frontend (chứa Web 1 và Web 2).
  • /api/: Chuyển tiếp tới Flask Backend tại cổng nội bộ 8081, tự động cắt bỏ tiền tố /api/.
  • /student và /student/: Chuyển tiếp trực tiếp tới endpoint xử lý danh sách sinh viên JSON.
  • /auth/: Chuyển tiếp tới Keycloak OIDC Server.

3. Cân bằng tải Round Robin giữa hai máy chủ Web

Để đảm bảo tính sẵn sàng cao (High Availability), chúng ta xây dựng 2 container Web độc lập: web-frontend-server1 và web-frontend-server2. Nginx Gateway khai báo khối upstream web_cluster với thuật toán Round Robin mặc định. Mỗi request gửi đến trang chủ sẽ được chuyển đổi luân phiên qua từng server, giúp phân tán tải và ngăn ngừa tình trạng thắt cổ chai ở một node duy nhất.
